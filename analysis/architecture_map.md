Roles come from the segment layout: **PROGRAM** = segment of `entry` (the compiled BASIC code), **STARTUP** = segment of the first far call from `entry` (relocates the data segment), **RUNTIME** = segment that receives the program's far calls (the linked IBM BASIC runtime).

**Important limitation.** The compiler puts a one-byte `INT3` after most runtime calls as a statement marker, and Ghidra treats `INT3` as the end of a function. `Gato1.exe` and `DEMO.EXE` therefore have almost their whole BASIC program (39 KB and 24 KB) marked as undefined data in the export, and only the runtime functions reachable from `entry` were recovered. This script re-sweeps the program bytes itself and reports the result as *regions* (section 5), not as Ghidra functions.

## 3. GATO.EXE -> other programs: the handoff

### 3.1 Mechanism

* **No DOS EXEC.** INT 21h with AH=4Bh is executed 0 times in total across the four binaries (per-binary: Gato 0, Gato1 0, DEMO 0, History 0). No `COMMON`, `CHAIN`, `COMMAND.COM`, `.BAT`, `.TMP`, `.CFG` or `.INI` string exists in any of them.
* **In-process loader.** `CHAIN` is the runtime routine `FUN_10a1_1757` (file 0x2767). It parses the name with INT 21h AH=29h, defaults the extension to `EXE`, opens it (AH=0Fh), reads the MZ header and image with AH=27h, applies relocations itself and `retf`s into the new entry point. The same routine is present in `DEMO.EXE` and `History.exe` (rows below); `Gato1.exe` has none.
* **Arguments / state.** The only argument is the file name (a BASIC string constant such as `DEMO`); the loader sets the DTA back to PSP:0080h and keeps the original PSP, so the command tail is unchanged and the new program receives **no command-line text**. The loader copies only a 0x58-word stub and the 0x20-word header/FCB buffer. No variables are passed (no `COMMON` block).

### 3.3 How `GATO.EXE` chooses

The three call sites are guarded by comparisons of the menu variable with the MBF constants [2.0, 3.0, 4.0]: `2` -> `DEMO`, `3` -> `HISTORY`, `4` -> END, otherwise `GATO1`. `DEMO.EXE` and `History.exe` each chain back to `GATO`; `Gato1.exe` ends the process.

## 6. Caveats

* Region boundaries and purposes are heuristics. Real BASIC subroutine boundaries (GOSUB targets) were not recovered because GOSUB/RETURN are runtime-mediated.
* Category tags are from instruction evidence in each routine (and for far-call targets, only the routine itself plus the `via` hint). A routine that merely calls a wrapper that executes `INT 10h` is *not* tagged video.
* Runs of tiny entry stubs that fall through into one shared body (for example the number-formatting stubs `FUN_199b_17ce`..`18ae` in Gato1) each carry the same evidence, so per-category counts are counts of *entry points*, not of distinct algorithms.
* 'FP math (MBF)' by multi-word arithmetic is a heuristic (>= 6 ADC/SBB/RCL/RCR); table references are exact.
